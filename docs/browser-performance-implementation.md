## 实施顺序

1. 固定baseline；增加工作线程等待/提交阻塞/尾部回收/复制/预览/core子阶段计时和retained bytes，输出可复核诊断。计时不改变图像/算法。
2. ccl_image：紧密Gray8直接借用，padding逐行压紧；每worker独占workspace；复用分割主要缓冲与Matcher(family,max_hamming)。保持稳定边排序、float顺序、边框初始化、预算拒绝、取消失败合同。避免workspace将原先分阶段数组永久叠加。
3. 浏览器：有界小读窗口，大读直通；复用同一授权身份/revision的bag reader元数据，避免重复open扫描。缓存至多一个source，绑定失效正确清理，不缓存整文件。不新增第二份corebag解析器。
4. 依据队列证据决定submit/finish回收改造；不盲目加线程、放大队列或换MPMC。保留预览显示，提供独立诊断关闭源头生成以分离显示/生成成本。
5. 一次针对性测试批次：coreworkspace连续复用、尺寸/格式/padding、错误后恢复；应用输入与JS读取边界；CPU单/多线程WASM；浏览器实际真实输入、容器smoke、取消。测试失败修复后仅重跑受影响路径。
6. 交错baseline/候选真实浏览器对照；比对完整观测而不仅点数、最终参数/残差/有效帧点数、IO与阶段耗时。报告中明确速度提升与重复读取节省的关系，不叠加重叠时间。
